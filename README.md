# WTAutoPilot — 战雷空战自动驾驶


空战自动驾驶脚本 + WebUI。
## 流程
读取8111数据 -> 飞控控制 -> 模拟按键操作
在webUI中可以上传你自己的按键设置`blk`文件，调节pd参数
## 注意
仅用于自定义任务以及离线任务环境，在多人游戏中使用脚本违反用户协议3.2.3。

## 快速开始

```bash
pip install -r requirements.txt

# 离线模拟器演示：不需要开游戏，也不碰 8111
python run.py --source sim --open

# 连真游戏（需要游戏已经进入空战、8111 在更新）
python run.py --source http --open
```

`--source` 不写的话就用 `config/config.json` 里存的值，所以连真游戏时**显式写上 `--source http`**
最稳（界面上「数据源」那一格也会显示当前到底连的是哪个）。

浏览器打开 `http://127.0.0.1:8112/`。选一个模式 → 点 **接通** → 切回游戏窗口。
**注意**：默认只在游戏窗口处于前台时才发送按键，否则会拒绝输出（避免把 W/S/A/D 打进浏览器输入框）。
状态栏里的「焦点」会显示当前是否满足条件。

命令行无界面模式（调试用）：

```bash
python run.py --console navigate --source sim --seconds 30
```

## 1. 读取 8111 的数据

游戏在空战中会持续提供这几个端点，全部是只读的：

| 端点 | 用途 | 用到的字段 |
| --- | --- | --- |
| `/state` | 主要飞行数据 | `H, m` 高度、`IAS, km/h`、`TAS, km/h`、`Vy, m/s` 爬升率、`throttle 1, %` |
| `/indicators` | 座舱仪表 | `compass` 罗盘航向、`aviahorizon_roll/pitch` 姿态、`vario` 爬升率、`radio_altitude` |
| `/map_obj.json` | 地图目标 | `point_of_interest` 目标点、`icon=Player` 本机（含 `x,y` 位置与 `dx,dy` 朝向矢量）、敌机 |
| `/map_info.json` | 地图边界 | `map_min`/`map_max`，把归一化坐标换算成米 |

每个端点都是可选的：某个请求失败只会让它负责的那部分字段留空，不会中断控制循环。
`map_info.json` 缺失时用默认地图尺寸兜底——方位角不受影响，只有距离会变成估计值。

## 2. 飞控

实现三种模式

* **stabilize 保持稳定** — 机翼改平、俯仰归零。不做任何目标跟踪。
* **alt_hold 确定高度** — 保持**指定高度** + 飞向目标点。
  目标高度填在界面上这一行旁边的输入框里；留空 = 保持接通那一刻的高度。
* **navigate 飞往目标点** — 保持**接通那一刻的高度**，边压坡度转向 `point_of_interest`，
  进入 `arrive_radius_m` 后报告 arrived。目标高度是 alt_hold 专属设置，navigate 不看它。

控制（`control.py`）：

```
航向误差 → 目标坡度     roll_target = clamp(k_heading × 航向误差, ±max_bank)     （PD 策略）
坡度误差 → 副翼         aileron  = clamp(kp_roll  × (roll_target − roll) − kd_roll  × 坡度角速度, ±1)
高度误差 → 目标俯仰     |误差| > 200 m : ±7°（固定姿态）
                        |误差| ≤ 200 m : clamp(alt_kp × 误差 − vario_kd × 爬升率, ±max_pitch)
                        （两种策略共用，再过一遍 ±10 °/s 速率限制）
俯仰误差 → 升降舵       elevator = clamp(kp_pitch × (pitch_target − pitch) − kd_pitch × 俯仰角速度, ±1)
```

按键是开关量，没法直接表达 -1…+1 的连续杆量，所以用 `DitherAxis` 做占空比调制：
需要的杆量越大，一个循环周期内按住该键的 tick 比例越高，平均杆量就越大。
好处是不用在循环里 `sleep`（不影响时序），而且多个轴可以同时动作。

### 各参数的作用

#### 航向控制策略选择

界面上「航向控制策略」一项有两个选项。**它只影响航向通道**（航向误差 → 目标坡度），
高度通道两种策略共用同一条律法（见下一节）。

| 策略 | 说明 | 适用场景 |
| --- | --- | --- |
| **PD 连续**（默认） | 原始的连续 PD 控制，航向误差线性映射到目标坡度。保留阻尼项 `roll_kd`/`pitch_kd` 防振荡。**平滑连续，但需要精确调参**。 | 已经掌握飞机响应规律、追求精细控制 |
| **分段控制** | 参考 Aokana-Flying-Circus 的分段控制思路，把航向误差分成多档，每档对应不同的目标坡度。航向误差 >15° 用大坡度急转，3-7° 用小坡度微调。**直观好调，对参数不敏感**。 | 首次上手、还没摸清飞机响应；快速原型验证 |

分段控制的**航向档位**（默认）：

| 航向误差 | 目标坡度 |
| --- | --- |
| \|误差\| > 15° | 35°（急转） |
| \|误差\| > 7° | 20°（中转） |
| \|误差\| > 3° | 10°（微调） |
| \|误差\| > 0.5° | 3°（修整） |
| 更小 | 0°（稳住） |

如果需要自定义航向分段（比如针对特定机型调参），可以在 `FlightController` 上调用 `set_heading_zones()`。

---

#### 高度控制律：远距固定俯仰 + 近距 PD

高度通道**不分策略**，永远走这条两段式行为（阈值写死在 `control.py`，不在界面上暴露）：

| 高度误差 | 目标俯仰 | 说明 |
| --- | --- | --- |
| **> 200 m** | **±7° 固定** | 长时间保持一个恒定姿态，让飞机稳定在一个爬升/下降率上。**与误差大小无关**（差 250 m 和差 5000 m 都是 7°），也**不叠加 `vario` 阻尼** |
| **≤ 200 m** | `alt_kp × 误差 − vario_kd × 爬升率`，限幅 `±max_pitch_deg` | 换回 PD 精细收口，带爬升率阻尼 |

两段的结果都会再过一遍**俯仰目标速率限制**：`pitch_target` 每拍最多变化 `10 °/s`。
没有它，切换点会阶跃——理论上最多跳 `7 + max_pitch_deg = 27°`（反向大爬升率时 PD 输出可以是
`−max_pitch_deg`），实测也能到 6.6° / 一拍（等效 132 °/s）。

几个必须知道的固有代价：

* **固定段在姿态上是开环的**。「保持姿态」就是这个意思——它不按误差比例追，也不看爬升率，
  所以进入 200 m 带之前 phugoid 不受阻尼。这是律法的固有属性，不是 bug。
* **低空拉起权限变弱了**：以前误差大时俯仰能顶到 `max_pitch_deg`（20°），现在一律只有 7°。
  `min_altitude_m` 是**硬脱开**（释放全部按键），不是自动救机模式——别指望它救命。
* **`navigate` 也会走这条律法**，但它的目标是接通那一刻捕获的高度，误差通常是 0，
  基本不会进固定段。这正是想要的行为。

---

#### PD 控制的增益表

先澄清一点：`control.py` 里已经没有 PID 类了——高度通道的 Far 段是固定姿态，Near 段和航向
通道都是纯 PD（比例 + 微分），**没有任何积分项**。因为游戏的遥测刷新率不稳定，积分项需要可靠
的时间基准才不发散；纯 PD 对这种「本身有阻尼」的对象够用，代价是稳态有残差——这正是
`alt_kp` 那条要留意的。

四条通道是**级联**的，从外到内：航向 → 坡度 → 副翼，高度 → 俯仰 → 升降舵。

| 参数 | 默认 | 作用 | 单位 | 调大的后果 | 调小的后果 |
| --- | --- | --- | --- | --- | --- |
| `heading_kp` | 1.20 | 外环：航向误差 → 目标坡度 | °坡度 / °航向误差 | 回到航向更快，但会在航向上来回摆 | 转弯迟钝，要偏很远才压满坡度 |
| `max_bank_deg` | 45 | `roll_target` 的饱和限幅，同时决定最大转弯率 | ° | 转弯更快，但掉高度掉速更狠 | 转弯慢 |
| `roll_kp` | 0.040 | 副翼 P：坡度误差 → 副翼 | 归一化副翼 / °坡度误差 | 压坡度更干脆，过头会滚转振荡 | 建立坡度慢 |
| `roll_kd` | 0.0030 | 副翼 D：坡度角速度阻尼 | 归一化副翼 / (°/s) | 压制滚转振荡，过大会发抖、变钝 | 收敛慢、容易超调 |
| `alt_kp` | 0.020 | 高度误差 → 目标俯仰 | °俯仰 / m | 抓高度积极，容易顶到 `max_pitch_deg` 并掉速 | 高度修正很慢 |
| `vario_kd` | 0.250 | 爬升率阻尼，等效高度环的 D（用实测 Vy 而不是对高度差分，噪声小得多） | °俯仰 / (m/s) | 抑制「拉起—掉速—再拉起」的振荡，过大会压着机头爬不上去 | 高度过冲、来回喘 |
| `max_pitch_deg` | 20 | `pitch_target` 的饱和限幅 | ° | 爬升/抓高度更快，但掉速 | 爬升能力不足 |
| `pitch_kp` | 0.080 | 升降舵 P：俯仰误差 → 升降舵 | 归一化升降舵 / °俯仰误差 | 跟俯仰更紧，过头会长周期振荡 | 俯仰跟不上目标，低速时明显 |
| `pitch_kd` | 0.0100 | 升降舵 D：俯仰角速度阻尼 | 归一化升降舵 / (°/s) | 抑制长周期摆荡，过大会迟钝 | 俯仰来回荡 |
| `axis_deadband` | 0.06 | 杆量绝对值低于此值直接回中，不发按键 | 归一化杆量 | 按键更稳、少误触，但小修正全丢 | 小杆量也开始打键，键输出更碎 |
| `tick_hz` | 20 | 控制循环频率（**不是增益**） | Hz | 控制更细，但按键与遥测请求更密 | 控制粗糙，D 项噪声变大 |

三个「读这几个数」的速算，方便判断参数是否调过头：

* 航向误差超过 `max_bank_deg / heading_kp` ≈ **37°** 时压满坡度；
* 高度差超过 `max_pitch_deg / alt_kp` = **1000 m** 时 PD 分支会顶到限幅——但实测意义不大，
  因为高度差超过 **200 m** 就已经切到固定的 ±7° 段了，PD 的输出范围通常用不满；
* 爬升率要到 `max_pitch_deg / vario_kd` = **80 m/s** 才能把俯仰需求完全吃掉——
  现实中到不了，所以 `vario_kd` 只起阻尼作用，不会锁死爬升。

顺带一个容易踩的坑：`pitch_kp` 太小会让固定段的杆量被 `axis_deadband` 吃掉。模拟器内环
稳态是 `pitch = pitch_kp × (目标 − pitch) × 25`，`pitch_kp = 0.08` 时闭环 DC 增益约 2/3，
7° 目标实际压到 4.67°，稳态杆量 ≈ 0.19，越过 0.03 的死区绰绰有余；但如果 `pitch_kp`
退回 0.02，杆量只有 0.093，和默认死区同量级，升降舵会**完全不输出**。

非增益的参数：

| 参数 | 默认 | 作用 |
| --- | --- | --- |
| `target_heading_deg` | 留空 | alt_hold 的航向目标；留空 = 保持接通那一刻的航向 |
| `arrive_radius_m` | 400 | navigate 判定「到达」的半径 |
| `min_altitude_m` | 150 | 低于此高度立即脱开并释放全部按键 |
| `use_throttle` / `target_speed_kmh` / `throttle_kp` | 关 / 500 / 0.004 | 速度环，默认关——高度用俯仰就压得住，而油门绑定本身有歧义 |
| `use_rudder` / `rudder_kp` | 关 / 0.010 | 方向舵偏航，默认关——参考 key.blk 里没有绑定方向舵 |

`target_altitude_m` 不在这张表里，因为它只对 alt_hold 有意义：界面上它是
「确定高度」那一行旁边的输入框（见下面的 WebUI 一节），navigate 用的是接通时刻的高度。

### 符号约定



* **地图朝向**：纯被动学习。飞行中比较”朝向矢量的地图角变化”和”罗盘航向变化”，
  变化量累积到 3° 以上才投一票，票数够了就确定 `map_sign`。之后方位角用相对几何算
  ——本机朝向矢量到目标矢量的夹角 + 罗盘航向——地图旋转量自动约掉，不依赖地图单位。
* **仪表符号**：`aviahorizon_roll` 和 `aviahorizon_pitch` 的正负号与标准约定相反，
  因此默认 `roll_sign = -1`、`pitch_sign = -1`。这是根据 War Thunder 的实际行为确定的。

## 3. 按键（key.blk）

`key.blk` 里 `hotkeys` 段的键盘绑定就是 DirectInput 扫描码。解析结果：

| 动作 | 来源 | 键 |
| --- | --- | --- |
| 抬头 / 低头 | `elevator_rangeMax` / `Min` | S (31) / W (17) |
| 右滚 / 左滚 | `ailerons_rangeMax` / `Min` | D (32) / A (30) |
| 方向舵左右 | `rudder_rangeMax` / `Min` | Q(16) / E(18) |
| 减速板 / 襟翼 / 起落架 | `ID_AIR_BRAKE` / `ID_FLAPS_*` / `ID_GEAR` | G / R,F / H |

两个值得说明的取舍：

* **扩展键位**：扫描码 ≥128 表示扩展键（`NUMPAD9_EXT` 这类）。同一个动作在
  `key.blk` 里可能有多个绑定（油门就是 `NUMPAD9_EXT, F1, NUMPAD9` 三个）。
  代码**只挑一个**按键——同时按住三个太容易误触发别的功能（F1 在游戏里会触发别的东西）。
  选择顺序：非功能键 > 非扩展键 > 码值小者，所以油门选中 NUMPAD9 而不是 F1。
  WebUI 会把文件里提供的全部候选列出来，用户可以手动覆盖。
* **组合键**：一个绑定块里有多个 `keyboardKey` 表示 Alt+Ctrl 这种组合，脚本不会采用。

注入方式是 `SendInput` + `KEYEVENTF_SCANCODE`（DirectInput 游戏吃硬件扫描码），
扩展键补 `KEYEVENTF_EXTENDEDKEY`。异常状态 `release_all()`，
不会出现按键卡住不放。`--dry-run` / 模拟器模式下强制使用空 sink，绝不注入。

## 4. WebUI

`http://127.0.0.1:8112/`：实时遥测、控制量柱状图、目标方位/距离、模式选择、
参数实时调、按键覆盖表、`.blk` 上传（拖拽或点击，非 `.blk` 会被拒绝）、连接设置。
**目标高度**是「确定高度」那一行右侧的输入框，选中该模式才会启用（留空 = 保持当前高度）。
界面是中文的；按钮依次是 **接通 / 脱开 / 切到游戏**，参数区是各增益的中文名，
按键绑定表里同时显示中文动作名和 API 用的英文标识（如 `elevator_up`）。
前端每 400 ms 轮询 `/api/status`。

数据源可以随时切换：**战争雷霆（localhost:8111）**、**离线模拟器**、**录制的抓包（ref/）**。

REST 接口：`/api/status`、`/api/config`、`/api/params`、`/api/engage`、`/api/disengage`、
`/api/focus`、`/api/bindings`（GET/POST）、`/api/upload_blk`、`/api/settings`。

## 安全

* 只有游戏窗口在前台才发送按键（`require_focus`，界面可关）。
* 低于 `min_altitude_m` 立即脱开并释放所有按键。
* 遥测中断、失焦、异常、Ctrl+C / 进程退出都会释放全部按键。

## 已知局限

* **仅在少数实机验证过**：ai进行的全部验证都在离线模拟器
  和 `ref/` 抓包上完成（36 个离线测试）。为适应不同真机首飞请先在安全高度、用
  `stabilize` 试，并调节pd参数。
* 油门控制默认关闭（`use_throttle`）：智能调节油门轴将在未来实现。
  想用的话在界面上打开。
* 到达目标点是**飞越**，不是盘旋停留——它会飞过去然后掉头再来。
* 参数（PD 增益等）是按模拟器的响应手调的起点，真机可能需要重新调；
  界面里可以实时改。
* `aviahorizon_roll/pitch` 与 `bank` 两个字段在参考数据里数值接近、无法区分，
  代码优先取 `aviahorizon_*`，符号默认为 -1。
